## 目录约定

```
assets/pet/cat/source/master-raw.png    ★ 母图真源（图像生成器直接产出，不进 build）
assets/pet/cat/build/                   管线中间产物（.gitignore 掉了，可随时重跑）
    master-keyed.png                    抠底后的母图（真正带 alpha 的那张）
    parts/<id>.png                      拆出来的部件
    parts/_segmap.png                   分区图（拆件依据，见 step2）
assets/pet/cat/{model.json,tex/,feat/}  最终形象包（运行时读的，进仓库）
```

**判据**：一个文件要进仓库，当且仅当「**重跑管线也生不出它**」。
母图是生成出来的（模型不可复现）→ 进仓库；抠底图、分区图、部件都能重跑 → 只进 `build/`。

## 坐标换算（从 `model.json` + `renderer/pet/cat-figure.js` 反推，已用旧形象包验证）

```
U(x) = 128 + (x - X0) * S          母版像素 x  -> rig 单位
V(y) = 256 - (FEET - y) * S        母版像素 y  -> rig 单位
母版 x = X0 + (u - 128) / S
母版 y = FEET - (256 - v) / S
```

- `parts[].box = [x, y, w, h]` 是 **rig 单位**；贴图像素数 = box 尺寸 ÷ S。
- 自检：旧形象包 `bangs` 的 box 是 67.78×65.2，贴图实测 367×353 —— 367 = 67.78 / 0.1847 ✓
- 旧形象包：`S=0.1847 X0=736 FEET=1470`，14 个部件合成后占母版 px (451,84)-(1186,1469)，
  即母版约 1278×1470。

## 每一步

**run_all.py — 一把梭（按配方跑）**

```
python tools/pet/pipeline/run_all.py cat
```

读 `assets/pet/<skin>/source/pipeline.json` 的配方（色彩系数等），依次跑 step0 → step1 →
（step2 / step3 写好后自动接上）。每一步也能单独跑，跑挂了只重跑那一步。

**step0_tone.py — 蓝色收敛（已跑通）**

```
python tools/pet/pipeline/step0_tone.py <输入.png> <输出.png> 0.62
python tools/pet/pipeline/step0_tone.py <图.png> --measure      # 只看不改
```

图像生成器出的母图蓝色容易过鲜。口径是「蓝色像素的平均 B−R」（旧母版 80.0）：

| | B−R |
| --- | --- |
| 旧母版截图（星宝给的） | 80.0 |
| 第一版新母图（链式迭代 3 轮） | 65.7 |
| 定稿母图（一次成型） | 149.6 |
| × 0.62 收敛后（**采用**） | **99.2** |

只按**色相**动蓝色区（H 185~265），皮肤 / 腮红 / 描边 / 白色一律不碰。
**别用「重出一版」来调色**：那会再引入一轮画风漂移，而且不可复现。

⚠️ **别链式图生图**。第一版母图是 `V1 → N1 → N1c` 三轮迭代出来的，蓝色掉了 18%
（80 → 65.7），而且头发被画成接近背景的白灰 —— 星宝的反馈是「没扣干净、右边头发
还带着背景、蓝色有点淡了」。真正的修法是**回到原始参考图一次成型**。

**step1_key.py — 抠底（已跑通）**

```
python tools/pet/pipeline/step1_key.py assets/pet/cat/source/master-raw.png \
       assets/pet/cat/build/master-keyed.png
```

图像生成器即使收到 `background: transparent`，返回的也常是 **RGB 图**：背景被画成
棋盘格或者留白底。不能按「白色 → 透明」直接 key —— 角色的头发 / 围裙 / 袜子全是白，
一 key 就漏。做法是**从画布四边洪泛填充**：只有和边界连通的浅色才是真背景；角色内部的
白色被深色描边封着，走不进去。描边有缺口时会报错退出（洪泛占比 > 90%），不静默产出坏图。

**step2_import.py — 导入拆件交接包（★优先路径）**

```
python tools/pet/pipeline/step2_import.py assets/pet/cat/source/交接包 assets/pet/cat/build
```

**这套优先于下面的分水岭**：交接包是专门为 Live2D 绑定做的手工级拆件，实测
**27 层、全画布 2048×2048 保留原坐标**，图层并集 = 角色的 **99.999%**（只差 17 像素）、
多出 0。它用的**就是同一张母图**（角色 bbox 与 8 个随机采样点的 RGB+alpha 逐字节相同），
所以坐标能直接对上。

比自动拆件强的地方：没有分水岭的碎块/漫错；耳朵分内衬+外层、蓝色内发与后发分开、
鞋单独、脖颈单独；还带**画好的**闭眼睫毛线与两种嘴型。

⚠️ **两个坑**：

1. `00_未分配像素补齐层` **不能直接当部件**（它自己的文档也写明「只用于中性姿态检查、
   不可单独绑定」），但也**不能丢** —— 实测它装了 **27 万像素（角色的 17%）**，
   是层与层之间的半透明/抗锯齿软边。当静态层留着会让部件一动就露出不跟动的残影；
   丢掉则角色的 17% 变透明。**正解是按距离把每个像素分给最近的部件**（脚本已实现）。
2. 交接包**要进版本库**（`assets/pet/cat/source/交接包/`）：它是手工拆的、管线生不出来，
   按「一个文件进仓库当且仅当重跑管线也生不出它」的判据，它属于真源。
   但原始 **80.8 MB** 太大 —— 用同一套贴图瘦身（alpha 量化 8 阶 + 全透明处 RGB 清零）
   压到 **4.0 MB（省 95%）**，画质无损（省的全是压缩开销）。

**step2_parts.py — 分水岭拆件（兜底路径）**

没有交接包时用它：种子点 + 分水岭（描边当硬墙）+ 几何夹取。

⚠️ **先记住「描边即分割线 → 连通区域」这条自动路不成立**（实测，2026-10-09）：

| 描边阈值 | 区域数 | 最大一块占角色 |
| --- | --- | --- |
| 150 | 3023 | 48.8% |
| 195 | 2011 | 29.2% |
| 210 | 3013 | 20.8% |
| 225 | 8036 | 3.4%（但描边吃掉 77.5% 的角色，不可用）|

头 / 身体 / 头发在这些阈值下**总能连成一片** —— 母版的描边不构成闭合轮廓。
再叠上星宝的反馈「乱选抠图顺序，一些部位连在一起了」，结论一致：
**粘连的根因是没有显式边界，不是顺序**。

```
python tools/pet/pipeline/step2_parts.py assets/pet/cat/build/master-keyed.png \
       assets/pet/cat/build
```

地形 = **描边处一道硬墙（10000）+ 别处很低的坡度**。描边用**黑帽变换**
（`grey_closing(g,9) - g > 10`）找，不是卡绝对亮度 —— 这个母版的内部描边是中灰蓝，
卡亮度要么漏内部描边、要么把整片蓝裙子吃掉。用「梯度」当地形也不行：梯度只让穿越
**变贵**而不是**不可通行**，大块照样互相吞并（`arm_right` 22 万像素）。

**必须跑两遍**：第一遍纯按种子长；然后把「脸 / 双臂」用规则算出的显式区域当**标记**、
把旧标号清零，再跑第二遍 —— 只往后加像素是不够的，被腾出来的像素需要有新归属。
（第一版只加不减，`arm_right` 一个像素都没变。）

几条硬规矩，都是踩出来的：

| 规矩 | 为什么 |
| --- | --- |
| **标记里绝对不能带上「矩形」** | 标记内的像素**永远是标记的**，分水岭不会去动它们。手臂的标记早先写成 `(dilate(hand) \| reg)`，`reg` 就是那个矩形 → 手臂的遮罩等于矩形（`arm_left` 填充率 81%），把旁边的头发、裙角全圈进去，**渲染出来就是「一块贴上去的方块、边界是直边」**（星宝的原话「图没扣好，一块一块的」）。正确做法：**只用手/关节这类「一定在部件内部」的小块当种子**，矩形只留作事后夹取 |
| 种子必须**自动吸附到最近的「非描边」实心像素** | 落在背景上 → 标号被静默丢掉（部件=0 px）；落在描边线上 → 只长得出几十像素 |
| 每个「口袋」都要放种子 | 尾巴是蓬松画法，内部细线把它切成十几个互不相通的口袋，一个种子只占一个 |
| 找脸上的五官前先 `binary_fill_holes` 再腐蚀 | 脸在眼睛处是**洞**，直接腐蚀洞还是洞，眼睛根本不在搜索范围里 |
| 眼睛**不要**用「非肤色块」找 | 试过 5 种形态学做法全失败：右眼**几乎贴着脸的右边缘**，一圈皮肤被刘海/后发压得很窄，任何收缩都会把它切掉；头发标号还会渗进眼窝，"排除头发"等于把眼睛一起排掉。**改用虹膜**：它是脸上唯一的高饱和蓝（`B−R > 40`），干净利落两块，再从虹膜长成整只眼 |
| 找五官**不要**排除头发 | 前发标号正好压在右眼上，一排除右虹膜就没了 |
| 脸底**不要**再 `& face_mask` | 眼睛在肤色里本来就是洞，与一次等于自己把五官排除掉（`feats` 直接变空） |
| 脸的贴图要把眼/嘴区**用肤色填平** | 否则 `eye_closed`（只画一条弧）会露出母图里睁着的眼珠 —— 旧管线就是这个问题 |
| 嘴 = 脸下半部中轴上的**暗块** | 「偏红」会圈进腮红；「最大暗块」会挑到下巴线，搜索区上界要卡在脸底之上 |

产物：`build/parts/<id>.png`、`build/parts/_parts.json`、`build/parts/_labels.npy`
（标号缓存，调规则不用重跑分水岭）、`build/_segmap.png`（**纯色分区图，看这个判断对不对**）、
`build/_seg_overlay.png`（分区色与原图混合）。

**还没做的**：`eye_closed`（旧管线是程序化画上凸弧）；双臂范围偏大（袖子贴衣身）；
step3（重量 pivots / box / view 并重建 model.json）。


**step3_pack.py / step4_install.py — 算 box 与 pivots、写 model.json、装进形象包**

```
python tools/pet/pipeline/step3_pack.py assets/pet/cat/build cat2
```

从 `build/parts/_parts.json` 算 rig box、写 pivots、写 `model.json`、把 tex/feat 拷进形象包，
并出一张**静置合成预览** `build/_pack_preview.png` ——
贴出来的东西应该和母图长得一样；对不上就是 **box / z 序**错了
（pivots 是动画用的，静置看不出来）。

⚠️ **三条必须记住的约定**（都在 `rig.js` 里验证过）：

1. `box = [x, y, w, h]` 是 rig 单位，**y 是 box 的顶边**，网格从 y **朝下**铺到 y+h。
   这个 rig 的 **v 是向下增大的** —— 顶点着色器 `gl_Position.y = 1 - n.y*2`，
   所以 `view.y0` 在屏幕顶、`view.y1` 在屏幕底；脚底 v=256 落在 view 底 276 之上
   20 单位，正是 `cat-figure.js` 的 `FEET_PAD`。（v 的朝向写反过两次，
   症状是「预览被压成一条线」和「一片 box 被误报超出 view」。）
2. `deformers` **不在 model.json 里** —— 变形器定义在 `cat-figure.js`，
   model.json 只记 `parent`（变形器链的起点）。
3. **pivots 用母版像素写**（脚本里的 `PIVOTS_PX` 表，每行注明是哪个关节），
   由脚本换算成 rig 单位 —— 将来对不上时一眼知道该调哪一行。

## 踩过的坑

1. **生成图的底色带噪点**：同一格灰散成上百种近似色，每种单独计数都不到阈值 ——
   第一版 `step1_key.py` 因此只认出深灰一种，浅灰格全留下，角色 bbox 直接铺满整张画布。
   修法：按 8 阶量化把近似色并起来再统计，并给「浅色低饱和」兜底。
2. **图像生成器不理会版面要求**：「把部件间隙画大」「角色占满画面」这类指令基本无效；
   角色在画面里的绝对尺寸由生成器定，换画布比例也没用（1024×1536 出 645，
   1536×1024 出 640），但**换更大的画布有用**（2048×2048 → 角色 1066×1860）。
3. **量尺寸别用预览图**：Read 工具看到的图是缩过的，量出来会差一倍（我因此先误报过
   645 px，实际 1324 px）。要量就写脚本读原图，用「描边像素（亮度 < 160）的 bbox」
   来定位角色 —— 背景和棋盘格都是浅色，不受影响。
4. **`00_未分配像素补齐层` 不是「洞」，是「跨边界的描边」**。它占角色 17%（27.6 万 px），
   一度被当成「有洞要填」，用「就近距离」分配 —— 结果把右后发填成深色方块、脸颊填出白三角。
   真相：**每个部件的边缘缺了一圈描边**，拼起来是一环环的缝（用户说的「东一块西一块」）。
   正解见下节。

## 接缝修补（`fix_holes3.py` / `fix_holes4.py`）

```
diag_holes.py   诊断：轮廓 - 内容 = 「只有 00 层在撑」的像素，开运算去渣后数连通块
fix_holes3.py   按颜色认领：取像素在 master-raw 里的颜色，比对邻近部件的**边缘色**
                （带空间惩罚），4 轮迭代。00 层 27.6 万 -> 11.4 万
fix_holes4.py   双边复制：剩下的是跨边界描边线，找两侧最近的两个部件，
                距离都够近就**两侧各留一份**（部件单独动时边缘必须自带描边）。00 层清零
```

**为什么必须「双边」而不是「二选一」**：一条边界描边，两侧部件分开动时，
如果只有一侧拥有它，另一侧转起来边缘就是秃的 —— 又变成缝。
实测 19.3% 的像素被 2 个部件共享、仅 0.2% 被 3 个共享，正是这个设计的结果。

**验收口径**（改完必跑）：

- **轮廓守恒 IoU 必须 = 1.0000**（一个像素不多不少）
- 母图自检漏掉 < 0.5%
- 关节露缝：肩部 < 3%、髋部 < 5%（髋部那个区被裙子盖住，看不见）

**用法**：`run_all.py` 会自动优先用 `layers_final`，不用手动指定。
要换回原版给 `step2_import.py` 传 `--layers layers`。

## ⚠️ 别拿外部 AI 重画的图去「对齐救」

Grok 重画的立绘和原卡**头宽/头高比**分别是 1.433 和 2.351 —— **是另一个比例的角色**
（耳小、头圆）。全身高宽比只差 1.1% 属**巧合**（头画小 + 身体画长互相抵消），
一旦对齐头部全身就散、对齐全身头部就散。**这类图只能当「姿态参考」，不能当图层源。**

## 另一条支线：`convert_whale.py`（搬别人的形象包）

上面 `step*.py` / `fix_holes*.py` 是**自己产形象包**（母图 → 拆件 → 打包）。
`convert_whale.py` 是**另一条路**：把 Coopanion 的鲸鱼包**转成** Mimitale 格式。

- 入口（**幂等**）：`python tools/pet/pipeline/convert_whale.py`
- 只认 `assets/pet/whale/source/model-original.json` 作输入 —— **不要读成品**，
  否则重跑是「在结果上再改」（踩过，见 `assets/pet/whale/README.md`）。
- 它踩过的两个坑**都值得单独记**（细节在 whale 的 README 里）：
  1. `feat` 的 box 宽公式**不是** parts 那套（`px_w*S` vs `px_w/S*DS`）；
  2. box 的 y 取 bbox **上边**（`V` 向下增长）—— 取错边整组五官下移一个自身高度。
- **搬任何外部形象包的通则**：凡 Coopanion 里出现 `st.alpha.X = <状态量>` 的部件，
  都要问「Mimitale 有没有那个状态」—— 没有就得删，否则它常驻并和正主**重叠**。
