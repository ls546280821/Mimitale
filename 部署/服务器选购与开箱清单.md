> 这份文档的作用是：**照着买、照着敲**。不需要做选型判断，判断已经做完了。
>
> 查价日期：2026-10-08。云厂商活动价变动频繁，**下单页的价格以页面为准**，
> 本文只负责告诉你"该看哪几个数字"。

## 0. 先明确：这台服务器要干什么

买之前必须知道买的是什么，否则很容易被"2核4G""5M带宽"这种参数带偏。

```
   ┌─────────────────┐
   │  Mimitale 客户端  │  用户自己电脑上跑
   │   (Electron)     │
   └────────┬────────┘
            │  ①登录 / ②校验卡密 / ③查额度
            │  （只是几次极小的 JSON 请求）
            ▼
   ┌─────────────────────────────────────┐
   │  中国香港 轻量服务器  ← 你要买这台     │
   │                                     │
   │   nginx ──> Spring Boot ──> MySQL   │
   │    ↑                                │
   │    └── 你自己的管理后台（浏览器打开） │
   └─────────────────────────────────────┘

   ★ 大模型请求（写故事、生图）走的是虚线，
     用户自带 Key 直连厂商，**永远不经过这台服务器**。
```

**所以这台机器实际要做的事只有三件：**

1. 存客户账号、卡密、额度、操作日志（数据量以 MB 计，一年也就几 MB）
2. 提供几个查询接口（QPS 大概是个位数，甚至经常为 0）
3. 托管管理后台的静态页面

**结论：CPU 和带宽基本都是浪费，内存和"数据别丢"才是重点。**
下面所有选型都是从这个结论推出来的 —— 所以你会看到我推荐"最低配"。

### 备选（如果阿里云香港只剩「国际型」，**直接走这条**）

**腾讯云轻量应用服务器 → 中国香港**。刊例价 2026-10-08 刚在官方《价格总览》核过：

| 套餐 | 配置 | 月价 | 跨境警告 | 流量 |

> 中国香港入门型套餐**无法保障中国内地与中国香港之间的跨境公网质量**，

这比那条针对所有港澳台产品的通用提示重，又比阿里云国际型的「仅适用于不服务

**所以腾讯云这里的买法是：**

1. **先按月买「入门型」38 元**（不买一年 —— 见下面的「时长折扣」）
2. 到手立刻 `ping -n 20 <IP>` 实测（判断标准在第 2 节 ⑤）：好就留着用
3. 丢包高 → **换成「锐驰型」55 元**（贵 17 元/月，还顺带解决了流量上限）
4. 锐驰型也不行 → 退款换厂商

⭐ **为什么敢只买一个月**：官方时长折扣**不覆盖 2核2G** ——

也就是说年付 = 38 × 12 = 456 元，**一分钱折扣都没有**，那当然按月买、
先花 38 块实测线路，零沉没成本。（下单页若有新人活动价另说，
那种注意看续费价就行，见第 2 节 ①。）

**为什么把这条提前**：阿里云香港现在主推的「**国际型**」用的是
**BGP（非中国优化）线路** —— 官方原文明确说不适合服务内地用户，见第 2 节第 ⑤ 条。
腾讯云香港的锐驰型/通用型没有这类警告（入门型有，所以先月付实测）。

### 为什么是这几个

**为什么必须香港？**
大陆节点必须备案才能用域名访问 80/443。而**个人备案明确不允许有登录、评论、
交互类功能** —— 我们这个客户端登录 + 后台管理正好全踩在上面。
香港节点免备案，可以立刻开工。（详见第 6 节）

**为什么是"轻量"不是"ECS"？**
轻量应用服务器 = CPU/内存 + 磁盘 + 带宽 + 流量 打包成一价，后台界面就是给你这种
单机场景做的（防火墙、快照、监控都在一个页面）。ECS 是给要组集群的人用的，
同样配置价格更高、还要单独买带宽和磁盘。
**这个项目永远是一台机器，没有第二个理由上 ECS。**

**为什么 2核2G 就够？**
算一笔内存账 —— **内存是唯一真实的瓶颈**，因为它是唯一不随用户数变的资源：

| 占用方 | 2核2G | 2核4G |
| --- | --- | --- |
| Ubuntu 系统本身 | ~200 MB | ~250 MB |
| MySQL 8 | ~300 MB（缓冲池 128M） | ~700 MB（缓冲池 512M） |
| Spring Boot | ~500 MB（`-Xmx320m`） | ~1.3 GB（`-Xmx1g`） |
| nginx | ~15 MB | ~20 MB |
| **合计** | **≈ 1 GB / 2 GB** | **≈ 2.3 GB / 4 GB** |

**两个都能跑。** 区别在余量：

- **2核2G**：剩 1 GB，够用，但 **JVM 和 MySQL 都得掐着给参数**，
  还得靠 3.4 节那个 2G swap 兜底 —— 是"精打细算地够用"
- **2核4G**：剩 1.7 GB，**不用想** —— 参数随便给，将来想加个 Redis 也有地方放

**该买哪个，看差价：**

| 情况 | 买 |
| --- | --- |
| 差价一倍以内（比如 408 vs 804 元/年） | **2核2G**，省下的钱够买域名 + 几年快照 |
| 差价无所谓、不想折腾参数 | **2核4G**，这份省心值这个钱 |
| 还打算跑别的东西（面板 / Docker / 第二个服务） | **2核4G** |

> ⚠️ **4G 不是"够不够"的问题，是"想不想省心"的问题。**
> 这个项目的负载（每秒几个 JSON 请求 + 一个管理页面）**2 核 CPU 极度富余**，
> 内存天花板也就 2 GB 出头 —— **4G 里大概有一半会一直是空的**。
> 所以买 2核2G 完全不算冒险，只是要照 3.10 节的参数调一下。

**只买一台。** 不需要"数据库单独一台""后台单独一台" —— 那套东西是给有运维团队的人
准备的，对这个项目是纯负担（多花钱、多一个要维护的东西、还得配内网互通）。
nginx + Spring Boot + MySQL 塞在同一台机器上，跑得动。

**为什么不要买 2核1G 甚至 2核0.5G？**
阿里云香港轻量确实有个"国际型 2核0.5G / 25元/月"的入门档。**不要买。**
MySQL 起不来，JVM 一跑就 OOM，省下的十几块钱会变成几个晚上的排查时间。

**为什么带宽随便？**
200M 峰值带宽对几个 JSON 请求是纯浪费。所以出现"30M 带宽的更便宜"时，
**买 30M 那个**，别为带宽付钱。唯一要看清的是**流量**（见下一节）。

## 2. 下单时要点开看的五个地方

这几个是真正会让人花冤枉钱、或者**买错东西**的地方，**下单页一定要展开确认**：

### ① 续费价 ≠ 首年价 ⚠️ 最容易踩

云厂商的"X 元/年"通常是**新购活动价**，第二年按目录价续费。
见过 288 元首年 → 648 元续费的档位，**翻了一倍多**。

**下单前必做**：在配置页面找"续费价""到期续费"之类的字样，或者直接把时长切到
**2 年/3 年**看总价 —— 活动价只覆盖第一年的话，切时长总价会跳。

> **省钱做法**：如果确认只有首年便宜，就买 1 年。续费期到了再比一次价，
> 那时候可能又有新活动，或者换家厂商（数据迁移成本对这个体量几乎为零，
> 一条 `mysqldump` + 一张一个文件的静态站）。

### ② 是不是"突发性能实例"（burstable）⚠️

部分低价 ECS/轻量是**突发性能**类型：CPU 基准性能只有 20%~50%，
平时靠"CPU 积分"攒着，**积分耗尽后被硬限频**。

对我们的场景其实无所谓（本来就没负载），但要知道自己买了什么。
识别方法：规格名里带 `t`（如 `ecs.t6`）、或者配置页写着"基准性能 xx%"。

**轻量应用服务器一般不是突发型**，是独享 CPU。这也是推荐轻量的原因之一。

### ③ 流量：先搞清"哪个方向算钱"、"超额了会怎样" ⭐

**一个反直觉但很关键的规则 —— 只有出站流量算钱**（腾讯云、阿里云都是这样）：

| 方向 | 对应什么操作 | 计费吗 |
| --- | --- | --- |
| **入站**（用户 → 服务器） | 客户端**上传**角色卡、提交登录 | ❌ **不计费**、不限量 |
| **出站**（服务器 → 用户） | 客户端**下载**角色卡、打开后台页面、API 返回 | ✅ **计费** |

所以真正要算的是**下载方向**。

**套餐两种口径：**

- **"不限流量"**（阿里云香港多数套餐）→ 首选，彻底不用想
- **"月流量包"**（腾讯云入门型 0.5TB / 1TB）→ 也够，但要会看

**0.5TB（512 GB）/ 月到底够不够？**

| 规模 | 出站流量 / 月 | 占 512 GB |
| --- | --- | --- |
| 10 个用户 | < 1 GB | 0.2% |
| 100 个用户 | ~10 GB | 2% |
| 1000 个用户 | ~90 GB | 18% |

（按"每人每次同步约 1 MB、每天 3 次"估）

**结论：512 GB 能撑 5000 个用户，早期连零头都用不到。**

**⚠️ 流量用尽后会发生什么？腾讯云官方口径是「按量计费」，不是限速：**

> 超出当月流量包限制：超出部分的流量将按照使用量进行计费……**按小时结算**
> —— 腾讯云《计费概述》

参考单价 **0.8 元/GB 上下**（各地域不同；**香港是 1.0 元/GB**，2026-10-08 官方
《价格总览》核实）。另外还有一条**联动规则**要注意：

> 账号**欠费** + 当月流量**超额** → 实例**停服**（进入"网络隔离中"状态）
> —— 腾讯云《欠费与停服说明》

**所以告警一定要开**：控制台 → 云监控 → 流量用到 80% 时发短信。
不然超额了你是从账单上发现的。

> ⚠️ **口径提醒**：网上不少文章说"流量用尽后限速到 1 Mbps"，但腾讯云**官方文档**
> 写的是"按量计费"。冲突时以官方为准，**下单前顺手在控制台确认一次**。
> （如果实际是限速，那反而更安全 —— 不会扣钱，只是变慢。）

**顺便把"峰值带宽"也说清楚：**

腾讯云官方文档原文：

> **峰值带宽不作为业务承诺指标**，当腾讯云在业务高峰期出现资源争抢时，公网带宽可能会受到限制

意思是 **20 Mbps 是"最高能跑多少"，不是"保证给你 20 Mbps"**。换算一下：
**20 Mbps ÷ 8 = 2.5 MB/s**，一个用户同步 1 MB 的角色卡，理想情况不到半秒。

**对咱们的负载（小 JSON + 一个后台页面）完全够。** 别被"峰值"两个字吓到 ——
它不是说"只能跑峰值的一小部分"。

> 早年的说法"这个项目一年流量不到 1GB"只在**用户个位数**时成立。
> 按上面的账，别拿它当长期结论。

### ④ 镜像：选"系统镜像"，别选"应用镜像"

下单页会让你选镜像，一般分两栏：

- **应用镜像** —— 预装好的 WordPress、宝塔面板、Docker 之类
- **系统镜像** —— 干净的操作系统 ✅ **选这个**

选 **Ubuntu 24.04 LTS**（或 22.04 LTS，都行，24.04 支持到 2029 年）。

> **为什么不选宝塔面板？** 宝塔会预装一整套环境（自己的 nginx、PHP、数据库、
> 监控），在 2G 内存上直接吃掉三五百 MB，还额外开放端口。它的价值是"不会 Linux 也能建站"，
> 而下面第 3 节已经把要敲的命令全给你了。
>
> **如果确实想要图形界面**：可以装宝塔，但要接受内存紧张，而且我不会帮你调它 ——
> 出了问题排查成本比省下的时间高。**建议先用命令行走一遍，不习惯再说。**

### ⑤ ⭐ 别选到「国际型」—— 它明确不适合服务内地用户 ⚠️

阿里云轻量现在分好几个**规格族**（通用型 / 容量型 / 多公网IP型 / 国际型 / CPU优化型）。
在香港地域**如果只看到「国际型」有货，别急着买**。官方文档原文（不是我的推断）：

> 国际型规格族采用 **BGP(非中国优化)公网线路，服务中国内地用户有较高的公网时延与丢包率，
> 仅适用于不需要对中国内地用户提供服务的应用场景**。

**而我们的用户 100% 在中国内地**（Mimitale 客户端用户 + 你自己用管理后台），
正好落在它明确劝退的那一类里。

**怎么办，按顺序试：**

| 顺序 | 做法 |
| --- | --- |
| 1 | 找阿里云香港的**通用型**、或**上一代轻量**（30M 带宽那代，普通 BGP）—— 有货就买 |
| 2 | 都没有 → **换腾讯云香港轻量**（入门型 / 锐驰型），线路不是"非中国优化" |
| 3 | 非要在阿里云买 → 买国际型，但**先测再决定留不留**，靠 5 天无理由退款兜底 |

**如果买了国际型，怎么判断要不要退**（买完立刻做，几分钟就好）：

```bash
ping -n 20 <你的服务器IP>     # Windows PowerShell 或 Git Bash 都行
```

看两个数：

| 平均延迟 | 丢包率 | 结论 |
| --- | --- | --- |
| < 100 ms | 0% | 很好，留着 |
| 100 ~ 200 ms | < 1% | 能用，但不如换家 |
| **> 200 ms，或丢包 > 2%** | | **退掉，换腾讯云** |

> **丢包比延迟更致命。** 这个项目全是小的 JSON 请求，**每丢一个包就要 TCP 重传**，
> 页面加载会被拖成好几秒。延迟高一点还能忍，丢包高不能忍。

⚠️ **退款有两个硬约束**（阿里云官方规则，别踩）：

1. **新购 5 个自然日内**才能无理由全额退，而且**每个自然年只有 1 次机会**
2. **买完千万别做续费 / 升级 / 换系统** —— 官方原文："新购五天内做过续费、升级、
   更换系统等操作，不支持五天无理由退款"

所以顺序是：**买 → 立刻 ping 测 → 满意就留着并开始配置；不满意就立刻退。
测之前别手痒改配置。**

## 3. 买完第一件事：开箱初始化

**照着从上往下敲**，每一步都说明为什么。假设你买的是 Ubuntu 24.04。

下面所有命令里的 `<你的IP>` 换成服务器的公网 IP。

### 3.1 先登录

在厂商控制台把 root 密码**重置一次**（首次登录前必须做，初始密码不显示）。

```bash
# 在你自己的电脑上（Git Bash / PowerShell 都行）
ssh root@<你的IP>
```

> 登录不上的话，先看控制台的**防火墙**是不是只开了 22 端口 —— 其实默认应该就开着。
> 实在连不上用控制台的"远程连接 / VNC"进网页版终端。

### 3.2 换 apt 源为国内公网镜像（可选但推荐）

香港机器默认走 `archive.ubuntu.com`，速度看运气。换成阿里云**公网**镜像（香港访问很快）：

```bash
# 先备份，改坏了能还原
sudo cp /etc/apt/sources.list.d/ubuntu.sources /etc/apt/sources.list.d/ubuntu.sources.bak

sudo sed -i 's|http://archive.ubuntu.com/ubuntu/|https://mirrors.aliyun.com/ubuntu/|g; s|http://security.ubuntu.com/ubuntu/|https://mirrors.aliyun.com/ubuntu/|g' /etc/apt/sources.list.d/ubuntu.sources

sudo apt update
```

> ⚠️ 注意用 `mirrors.aliyun.com`（公网），**不要**用 `mirrors.cloud.aliyuncs.com` ——
> 那个是阿里云**内网**域名，在轻量上解析不了，改了之后 `apt update` 会全部失败。

### 3.3 更新系统 + 设时区

```bash
sudo apt update && sudo apt -y upgrade
sudo timedatectl set-timezone Asia/Shanghai
date   # 确认输出是 CST 而不是 UTC
```

**时区必须设**。日志、卡密到期时间都按这个走，云服务器默认 UTC，
不设的话你会看到"日志时间是 8 小时前"这种诡异现象。

### 3.4 ⭐ 建 2G swap（2核2G 必做，2核4G 也建议留着）

**2核2G 的话这是最重要的一步**；2核4G 余量够，但照样建 —— swap 是**保命**用的，
不是拿来日常跑的。没有它，MySQL 和 JVM 争内存时会被 OOM Killer 直接杀进程
—— 表现是"服务莫名其妙挂了，日志里什么都没有"。

```bash
sudo fallocate -l 2G /swapfile
# 如果上面这条报 "fallocate failed: Operation not supported"，用下面这条代替：
# sudo dd if=/dev/zero of=/swapfile bs=1M count=2048

sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# 写进 fstab，重启后自动挂载
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# 降低换页倾向：能用真内存就别用 swap，swap 只当保命用
echo 'vm.swappiness=10' | sudo tee /etc/sysctl.d/99-swap.conf
sudo sysctl -p /etc/sysctl.d/99-swap.conf

# 验证：应该能看到 Swap 一行，大小 2.0Gi
free -h
```

### 3.5 建一个非 root 日常账号

一直用 root 干活，一条敲错的命令就是灾难。建个普通账号：

```bash
adduser mimitale          # 会让你设密码，随便设一个强的
usermod -aG sudo mimitale # 给它 sudo 权限

# 验证
su - mimitale
sudo whoami    # 应该输出 root
exit
```

### 3.6 ⭐ 配置 SSH 密钥登录，然后关掉密码登录

密码登录会被全网爆破（HK 节点的机器一天能被扫上万次，日志里全是 `Failed password`）。
密钥登录几乎无法被爆破。

**在你自己的电脑上**（不是服务器上）执行：

```bash
# 如果 ~/.ssh/id_ed25519 已存在就跳过这条
ssh-keygen -t ed25519 -C "mimitale"

# 把公钥传到服务器（会要 root 密码）
ssh-copy-id -i ~/.ssh/id_ed25519.pub mimitale@<你的IP>

# 验证：这次应该不问密码就进去了
ssh mimitale@<你的IP>
```

**能免密登录之后**，回到服务器上关掉密码登录：

```bash
sudo tee /etc/ssh/sshd_config.d/10-hardening.conf > /dev/null <<'EOF'
PermitRootLogin no
PasswordAuthentication no
EOF

sudo systemctl restart ssh

# 验证配置没写错（语法检查，输出为空表示没问题）
sudo sshd -t
```

> ⚠️ **顺序不能反**。先确认密钥能登录，再关密码。
> 反过来做而且密钥没配好，你就只能去控制台用 VNC 救自己了。

> 要不要把 SSH 端口从 22 改成别的？**不必**。改端口只挡得住最低级的扫描脚本，
> 密钥登录已经把门锁死了。改了端口反而容易忘记、给自己添麻烦。

### 3.7 防火墙：只开 22 / 80 / 443

**Linux 内部防火墙（ufw）：**

```bash
sudo apt -y install ufw

sudo ufw default deny incoming
sudo ufw default allow outgoing

sudo ufw allow 22/tcp     # SSH —— 必须开，否则 3.8 步会把自己锁在外面
sudo ufw allow 80/tcp     # HTTP（Let's Encrypt 验证要用）
sudo ufw allow 443/tcp    # HTTPS
```

**先确认上面三条都执行了，再开：**

```bash
sudo ufw enable           # 会问 "Command may disrupt existing ssh connections"，输 y
sudo ufw status verbose    # 检查一遍：22/80/443 是 ALLOW，其余是 deny
```

> ☠️ **经典自杀操作**：没放行 22 就直接 `ufw enable`，当前 SSH 连接还在（已建立的连接
> 不会被踢），但**一断开就再也连不上**，只能去控制台 VNC 里 `ufw disable` 救回来。
> 所以上面顺序是"先 allow 22，再 enable"，别调换。

**厂商控制台的防火墙（阿里云/腾讯云轻量里叫"防火墙"，ECS 里叫"安全组"）：**

这是**两层**防护，ufw 只管机器内部，厂商那层是云网络入口。
去控制台确认：**入方向只放行 22 / 80 / 443**。

> ⚠️ **8080 和 3306 绝对不要对公网开放。**
> - Spring Boot 的 8080 由 nginx 反代，只监听 `127.0.0.1`（配服务时再做）
> - MySQL 3306 同理，只监听本机。**3306 暴露到公网 = 几个小时内就会被挖矿脚本爆破**

### 3.8 打开自动安全更新

这台机器你一年可能都不登录几次，漏洞补丁得靠系统自己打：

```bash
sudo apt -y install unattended-upgrades
sudo dpkg-reconfigure --priority=low unattended-upgrades   # 弹出界面选 "Yes"

# 验证：应输出 enabled
systemctl is-enabled unattended-upgrades
```

> 注意：**只自动打安全补丁，不会自动重启**。如果内核更新了需要重启，
> 系统会写到 `/var/run/reboot-required`。看到了就找个时间手动 `sudo reboot`。

### 3.10 MySQL 初配（只做两件事）

**① 只监听本机**（防止 3306 意外暴露）：

```bash
sudo tee /etc/mysql/mysql.conf.d/99-mimitale.cnf > /dev/null <<'EOF'
[mysqld]
bind-address = 127.0.0.1
EOF

sudo systemctl restart mysql
sudo ss -tlnp | grep 3306    # 应显示 127.0.0.1:3306，不能是 0.0.0.0:3306
```

**② 建库建账号**：

```bash
sudo mysql <<'EOF'
CREATE DATABASE mimitale CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 密码换成你自己的，别用这个示例
CREATE USER 'mimitale'@'127.0.0.1' IDENTIFIED BY '换成你的强密码';

GRANT ALL PRIVILEGES ON mimitale.* TO 'mimitale'@'127.0.0.1';
FLUSH PRIVILEGES;
EOF

# 验证能连上
mysql -u mimitale -p -h 127.0.0.1 mimitale -e "SELECT VERSION();"
```

**③ 内存调优**（这台机器上只有 MySQL 和 JVM 抢内存，必须手动分配）：

**如果你是 2核2G：**

```bash
sudo tee -a /etc/mysql/mysql.conf.d/99-mimitale.cnf > /dev/null <<'EOF'

# 2G 内存：掐着给
innodb_buffer_pool_size = 128M
performance_schema = OFF
max_connections = 50
EOF

sudo systemctl restart mysql

# 看实际吃多少，应该在 200~300MB
ps -o rss= -C mysqld | awk '{print $1/1024" MB"}'
```

**如果你是 2核4G：**

```bash
sudo tee -a /etc/mysql/mysql.conf.d/99-mimitale.cnf > /dev/null <<'EOF'

# 4G 内存：宽松给，查询也更快
innodb_buffer_pool_size = 512M
performance_schema = OFF
max_connections = 100
EOF

sudo systemctl restart mysql

# 看实际吃多少，应该在 500~700MB
ps -o rss= -C mysqld | awk '{print $1/1024" MB"}'
```

> `performance_schema = OFF` 两边都要关 —— 它默认开着，会额外吃掉 100~200 MB，
> 而我们不需要那套细粒度监控（要看监控有云厂商的免费面板）。

### 3.12 ⭐ 开快照（别跳过）

**这是唯一能救回"数据库被误删"的东西。** 托管数据库有自动备份，
轻量自建 MySQL 没有 —— 你不开快照，数据就真的只有一份。

去厂商控制台：

- **阿里云轻量** → 左侧「快照」→ 创建快照。有免费额度（一般 3 个），超出几毛钱一个
- **腾讯云轻量** → 左侧「快照」→ 同样

**建议**：装完这一节之后**立刻手动打一个快照**，作为"干净基线"。
之后开**自动快照策略**（每周一次就很够）。

同时把**云监控告警**打开（免费）：CPU 持续 >80%、内存 >90% 时发短信。
配置好后它就是你的"服务器出事了"通知渠道。

### 3.13 ⭐ 开自动续费 / 到期提醒

轻量服务器**到期后不是"停服务"，是直接进回收站** —— 数据保留一段时间后销毁。
因为几十块钱的疏忽丢掉全部客户数据，不值得。

去控制台**费用中心 → 续费管理**：

- 如果确认会长期用 → 打开**自动续费**（注意它会按目录价扣，就是第 6 节说的那个更贵的价）
- 如果不确定 → 至少确认**到期提醒的短信/邮件是开着的**

同时确认账号里有**余额**，欠费是会直接停机的。

## 6. 内存、磁盘、流量 —— 谁跟着用户数长

这一节的目的是让你**买定之后不用再想服务器规格**。

| 资源 | 随用户数增长吗 | 100 用户 | 1000 用户 |
| --- | --- | --- | --- |
| **内存** | ❌ **不**（只跟"跑了几个进程"有关） | ~1 GB | ~1 GB |
| **CPU** | ❌ 几乎不（每秒几个请求） | 闲 | 闲 |
| **磁盘** | ✅ 会 | ~10 GB / 40 GB | ~12 GB / 40 GB |
| **流量** | ✅ **会，而且是最快的一项** | ~9 GB/月 | ~90 GB/月 |

**磁盘的账**（按"角色卡 + 世界书存服务器"估，约 1 MB / 人）：

| 项 | 100 用户 | 1000 用户 |
| --- | --- | --- |
| 系统 + JDK / MySQL / nginx | 8 GB | 8 GB |
| MySQL 数据（角色卡 + 世界书） | 100 MB | 1 GB |
| 头像文件（约 30 张 × 22 KB） | 66 MB | 660 MB |
| 日志（一年） | 1~2 GB | 1~2 GB |
| **合计** | **≈ 10 GB** | **≈ 12 GB** |

**40G 系统盘装 1000 个用户也才用掉三分之一。**

**流量的账**（**只算出站**，入站免费；一次全量同步约 1 MB / 人）：

| 规模 | 每天同步 3 次 | 每月 |
| --- | --- | --- |
| 100 用户 | 300 MB/天 | **~9 GB** |
| 1000 用户 | 3 GB/天 | **~90 GB** |

**所以套餐优先选"不限流量"**；选了流量包就选 1TB 档并打开告警
（超出 0.8~1 元/GB，90 GB 就是 90 块）。

> **一句话**：内存和 CPU 在买的时候定死，之后不用管；
> 磁盘和流量跟用户数一起长，但**长得很慢**。
> 唯一会让你想升级服务器的情况，是"哪天决定把对话记录也存上来" ——
> 那一下子就是 **10 倍**的数据量（见 `admin/登录体系决策记录.md` 决策 8）。

## 附：出事了怎么办（几个救急手法）

| 现象 | 先看这里 |
| --- | --- |
| SSH 连不上 | 控制台 VNC 进去，`sudo ufw status` / `systemctl status ssh` |
| 服务莫名其妙挂了 | `free -h` 看内存、`dmesg \| grep -i "killed process"` 看是不是被 OOM 杀了 |
| 网页打不开但 SSH 能进 | `systemctl status nginx`、`curl -I 127.0.0.1:8080`（看后端活没活） |
| 磁盘满了 | `du -sh /var/log/*`、`sudo apt autoremove` 清旧内核 |
| 想确认端口是不是暴露了 | `sudo ss -tlnp`，**看到 `0.0.0.0:3306` 就是出事，立刻改回 127.0.0.1** |
| 忘了 MySQL 密码 | 控制台 VNC 进，用 `sudo mysql`（root 走 socket，不要密码）改 |
