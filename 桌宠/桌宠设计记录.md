## 实现状态（2026-10-08）

方向没变，但落地时和下面这份设计有几处差异，以代码和 `CHANGELOG.md` 为准：

| 设计里写的 | 实际做的 | 为什么 |
| --- | --- | --- |
| 三道闸门（冷却 2 秒 / 有料 / 节流 N 轮） | **只留「每隔 N 轮」+ 临时静音** | 冷却和「有料」判断在用户眼里是玄学；「每隔几轮」是他能预期、能调的东西 |
| 三层触发（L1 状态 / L2 关键词 / L3 小模型） | **统一走一次模型调用** | 只发一小包上下文（会话名 + 最近 6 条 + 摘要 + 面板快照），成本可控；三层反而让「它为什么说这句」变得难解释 |
| 一期只做「看得见的最小闭环」 | 一期直接做完整版 | 星宝这次给的是完整需求清单，不是探路 |
| 右键菜单自绘 | **原生菜单**（Electron `Menu.popup`） | 窗口只有 300×380，带二级菜单的自绘菜单铺不下；原生菜单的二级、勾选态、点到外面关都是白拿的 |

代码落点：

- `main/pet-store.js` 设置 / 长期记忆 / 人格 / 形象路径
- `main/pet-window.js` 那个透明、置顶、**按像素**穿透鼠标的窗口
- `main/pet-brain.js` 拼提示词、调模型、把回复切成几句
- `main/pet-ipc.js` 通道注册 + 原生右键菜单 + 发言编排
- `preload-pet.js` 宠物窗口专用的窄桥（**和主 preload 分开，别合并**）
- `renderer/pet/` 宠物页面（独立文档 = 独立 CSP）
- `renderer/js/data/petContext.js` 上下文组装 + 触发计数
- `renderer/js/views/petSettings.js` 设置弹窗里的「桌宠」区块
- `tools/test-pet-store.js` 专项测试（55 条）
- `tools/pet/capture-pet-window.js` 真起一次窗口截图的校验脚本

## 一句话定位

**不是「角色的化身」，是坐在旁边看你跟角色玩的那个小家伙。**

它看得见对话、有自己的性格、会时不时插一句；但**它永远不进剧情**——
它是观众，不是演员。这个定位决定了下面每一条。

> 上一版方案（2026-10-08 早）走的是「角色化身」路线：把 `data/expressions.js` 的
> `stateCardPhoto()` 结果搬到桌面当角色的脸。**那条路作废**——星宝明确要的是独立宠物。
> 但 `expressions.js` 里那套**触发词机制**还有用，见下面 L2。

## 三条红线（先立规矩，后面全受它约束）

### 1. 宠物说的话**绝不能进会话历史**

`conversations.json` 的 `messages` 里出现一个字，角色下一轮就会"听见"宠物说话，
扮演立刻崩。所以：

- 宠物的话单独存 **`pets.json`**（滚动保留最近 N 条，N 默认 20）。
- 它**不进** `buildApiMessages` 的上下文组装，跟状态面板一个性质：是界面层的东西。

### 2. 点评**绝不能复用 `chat:send` 通道**（技术硬伤，已确认）

`main/ipc.js` 的 `chat:send` 里有两件事会让复用直接出事：

```js
if (activeController) { activeController.abort(); }        // ← 会把正在流的角色回复掐死
onDelta: (text) => sendToRenderer('chat:chunk', ...)       // ← 宠物的字会混进角色气泡
```

`activeController` 是**单例**，delta 只往 `chat:chunk` 一个频道推。
所以桌宠必须新开 **`pet:speak`** 通道，自己的 controller、自己的 `pet:chunk` 频道。
（顺带：`recordRequest()` 也该把宠物发的那次标上来源，见「开销要说清楚」。）

### 3. 宠物窗口**不能复用 `preload.js`**

现有 `preload.js` 暴露的 `getSettings` 返回**所有服务商的 API Key 明文**
（`main/window.js` 里那段 `will-navigate` 守卫的注释就是为它写的）。
宠物窗口要单独一份收窄的 `pet-preload.js`，只暴露 `window.petBridge`，
`contextIsolation: true` + `sandbox: true` 全开。

## 什么时候开口：三道闸门

```
角色回复完成
   ↓
① 冷却：再等约 2 秒        ← 不跟角色抢话
② 有料：这一轮值得说        ← 见「三层触发」
③ 节流：距上次开口 ≥ N 轮   ← 默认 3，可调 1~10，0 = 关
   ↓
三个都过 → 开口（L1/L2 免费，L3 才调模型）
```

两个**越过闸门**的例外：

- **用户点它** → 立刻催一句（"宠物，说说看"）。
- **刚进新会话 / 换角色** → 打个招呼（每个会话只打一次）。

## 说什么：三层触发，从免费到花钱

| 层 | 靠什么 | 花钱吗 |
| --- | --- | --- |
| **L1 状态字段变化** | 项目已有的状态面板字段（"好感 +5" / "心情 紧张"） | 不花 |
| **L2 关键词命中** | 复用 `data/expressions.js` 的触发词思路，加一组场景词 | 不花 |
| **L3 小模型点评** | 真需要一句成句的吐槽时才调 | 一次便宜调用 |

**L1 是主要信号，不是 L3。** 状态面板已经在替你把"刚才发生了什么事"结构化好了
（好感涨了、心情变了、时间过了），拿它当触发器比再读一遍正文准得多，而且免费。
像「你跟角色谈恋爱」这种场面，`好感` 连续上涨 + `心情` 在恋爱档位打转，
**不用模型就能判出来**，直接给针对性反馈。

L2 复用卡上已有的那套词：`expressions.js` 的 keywords 本来就是"害羞 / 脸红"这种
情绪词，同一套机制再加"表白 / 吵架 / 危险"这类**场面词**，就能判出该用什么语气。
（注意：这套匹配逻辑在**宿主侧**，插件/宠物只收结果，不收原始正文。）

L3 是兜底，不是主路。只有 L1/L2 判定"这场面值得说一句"、但模板话说不出来时才调。

## 给它看什么（成本控制的关键）

**绝不发完整 history**——那是 O(n²)，而且没必要。项目里已经有现成的两件东西，
直接复用，几乎零新增成本：

- `convoContextMessages(convo)` —— 已经按 `maxTurns` 裁好的最近对话
- `formatSummaryForPrompt(convo)` —— 早就压好的历史摘要

再补四样：

1. 当前角色名 + 状态字段快照（"好感 41 / 心情 紧张"）
2. **宠物自己的人设**（它是什么性格的小家伙、说话什么调调）—— 这是它的"角色卡"
3. 它自己上两句说过什么（防重复，不然会一直说同一句）
4. 一条对玩家的印象（"这个玩家喜欢撩人"）—— 可选，先不做

**输出约束：一句话，20~40 字，可以带一个 `*动作*`。** 解析直接抄
`renderer/js/data/suggestions.js` 的 `parseSuggestions()` 那套写法——容忍序号、
引号、超长截断、去重，都是现成的坑填好了。

## 模型从哪来

设置里加一组「桌宠」配置：`petEnabled` / `petProviderId` / `petModel` / `petEveryNTurns`。
默认**跟随当前会话模型**，但允许单独指到一个最便宜的模型（甚至本地 `tavern-bridge`）。

> ⚠️ **新增的设置键必须写进 `main/providers.js` 的 `DEFAULT_SETTINGS`。**
> `saveSettings` 的白名单是「默认设置里有 or 磁盘上本来就有」，漏掉的键会被**静默丢掉**
> （项目里踩过：`autoContinue` / `commonAttributes` 当初就漏了，怎么改都不生效，
> 只在主进程打一行没人看的 warn）。

## 除了说话还能干什么（全部免费）

都是纯前端动画，宿主推事件、宠物演：

| 事件 | 它演什么 |
| --- | --- |
| `chat:start` | 凑过来一起盯着看 |
| `chat:chunk` | 跟着打字的节奏晃 |
| `chat:done` | 听完歪头 / 记笔记 |
| `expression` 类变化 | 角色害羞时它捂眼睛，冲突时它抖一下 |
| 闲置 30 秒 | 打哈欠 / 转圈 / 睡着 |

素材建议用**精灵图 + 命名动画**（`idle` / `speak` / `happy` / `sad` / `sleep`），
思路跟 `character.expressions` 一致：**宿主只给"现在该是哪个状态"，宠物自己决定播哪段。**

窗口参数（三条都不能省）：

- `alwaysOnTop: 'screen-saver'`（普通 `alwaysOnTop` 会被其他窗口盖住）+ `skipTaskbar: true`
- **鼠标穿透**：`setIgnoreMouseEvents(true, { forward: true })` + 渲染层 `elementFromPoint`
  动态切。不做这条，桌面上会多一块**点击死区**，用户点不到下面的图标——桌宠最容易翻车的地方。
- **位置记忆按屏幕存**（相对哪个显示器 + 屏内坐标），显示器拔了要能回主屏。

## 开销要说清楚

点评 = 每 N 轮多一次请求。按 N=3 算，大约 **+20%~30% token**。所以：

- 设置里把频率写明白（"每 3 轮最多说一句"），别让它变成偷偷花钱的功能。
- 「请求记录」里标出来源（宠物发的请求单独标一条），让人看得见它在花钱。

## 分期

**一期：看得见的最小闭环。** 透明窗 + 拖拽 + 位置记忆 + 闲置动画 + 点击催一句
（**用固定模板，不调模型**）+ 主窗口里的总开关。
目的只有一个：先确认"它在桌面上不烦人"。这一步会把窗口参数那三个坑全踩一遍。

**二期：接三层触发 + 模型点评 + 节流**，把"陪伴感"做出来。一期验证过了再动手，
不然方向错了要连着窗口层一起返工。

**三期：插件化。** manifest / 权限白名单 / 导入别人的宠物，然后把**一期那只内置宠物
改写成"内置插件"**——狗粮自己吃，API 就被自动验证了。别跳过二期直接做三期。

## 待定旋钮（要拍板的）

1. **默认每几轮说一句？** 建议 3。这直接决定它是"存在感"还是"烦人"。
2. **默认用哪个模型？** 建议单独指定一个便宜的，不跟随主模型。
3. **会不会同时养多只？** 建议一期锁一只（架构上多只没难度，难的是别吵）。
4. **它有自己的长期记忆吗？** 建议只记"上两句说了什么"防重复 + 一条对玩家的印象，先不做长期记忆。
